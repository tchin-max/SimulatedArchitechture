3. Netzwerk-Framework: NetworkConnection.kt

3.1 Die Interfaces

interface Network {
    fun connect(address: String, handler: ConnectionHandler): EndPoint?
    fun provide(address: String, handler: ConnectionHandler): Boolean
    fun remove(address: String, handler: ConnectionHandler): Boolean
}

interface ConnectionHandler {
    fun onMsg(endPoint: EndPoint, msg: String)
    fun onData(endPoint: EndPoint, data: Any)
    fun onClose(endPoint: EndPoint)
    fun onOpen(endPoint: EndPoint)
}

interface EndPoint {
    fun sendMsg(msg: String)
    fun sendData(o: Any)
    fun close()
}

3.1.1 Interface Network

  • fun connect(address: String, handler: ConnectionHandler): EndPoint?
    – Ein Client ruft diese Methode auf, um sich zu verbinden.
    – address: z.B. "http://127.0.0.1:80/" oder "broker://local".
    – handler: Objekt, das die Callbacks (onOpen, onData, …) bekommt.
    – Rückgabewert: EndPoint? (nullable!)
      → Wenn null, gibt es keinen Server unter dieser Adresse.
      → Wenn nicht null, kann man über diesen Endpunkt senden.
  • fun provide(address: String, handler: ConnectionHandler): Boolean
    – Ein Server ruft diese Methode auf, um sich unter einer Adresse zu „registrieren“.
    – Rückgabewert: true, wenn die Adresse frei war; sonst false.
  • fun remove(address: String, handler: ConnectionHandler): Boolean
    – Meldet einen Server an einer Adresse wieder ab.
    – Wird in dieser Übung kaum genutzt, ist aber für Vollständigkeit da.

3.1.2 Interface ConnectionHandler

  • onOpen(endPoint: EndPoint) – wird aufgerufen, wenn eine neue Verbindung aufgebaut ist.
  • onClose(endPoint: EndPoint) – wird aufgerufen, wenn die Verbindung beendet wurde.
  • onMsg(endPoint: EndPoint, msg: String) – wird gerufen, wenn eine Text-Nachricht ankommt (via sendMsg).
  • onData(endPoint: EndPoint, data: Any) – wird gerufen, wenn ein Objekt ankommt (via sendData).

3.1.3 Interface EndPoint

  • sendMsg(msg: String) – Text an die andere Seite schicken.
  • sendData(o: Any) – beliebiges Objekt schicken (in der Übung meistens unsere data class-DTOs).
  • close() – Verbindung beenden.

3.2 SimpleNetwork & SimpleNetworkConnection – was passiert bei connect()?

Vereinfacht läuft der Verbindungsaufbau so ab (Pseudo-Code):

class SimpleNetwork : Network {
    private val providers = mutableMapOf<String, ConnectionHandler>()

    override fun provide(address: String, handler: ConnectionHandler): Boolean {
        if (providers.containsKey(address)) return false
        providers[address] = handler
        return true
    }

    override fun connect(address: String, handler: ConnectionHandler): EndPoint? {
        val serverHandler = providers[address] ?: return null
        val connection = SimpleNetworkConnection(handler, serverHandler)
        return connection.getClientEndPoint()
    }

    // ...
}

Wenn connect() aufgerufen wird:

  1. Das Network sucht nach einem Server-Handler unter dieser Adresse.
  2. Wenn keiner vorhanden ist → null zurück.
  3. Wenn vorhanden:
    • Es wird eine SimpleNetworkConnection erzeugt.
    • Die Connection legt einen leftEndPoint (Client-Sicht) und einen rightEndPoint (Server-Sicht) an.
    • Beide Seiten bekommen ihren jeweiligen ConnectionHandler.
  4. Die Connection ruft anschließend onOpen() bei Client und Server auf.
[ Client Handler ] <-- leftEndPoint -- SimpleNetworkConnection -- rightEndPoint --> [ Server Handler ]

Dadurch können wir später das gleiche Framework sowohl für den EchoServer als auch für den ChatServer und den Broker wiederverwenden.

4. EchoServer – Implementierung

4.1 Der Code

class EchoServer(val sn: SimpleNetwork, val address: String) {
    init {
        println("========= Start up server ========= ")
        val connected = sn.provide(address, object : ConnectionHandler {

            override fun onMsg(endPoint: EndPoint, msg: String) {
                println("SERVER, got msg: '$msg'")
                endPoint.sendMsg("<$msg>")
            }

            override fun onData(endPoint: EndPoint, data: Any) {

            }

            override fun onClose(endPoint: EndPoint) {

            }

            }
        })

        if (connected) {
            println("SERVER: listing to address $address")
        }
    }
}

4.2 Erklärung Zeile für Zeile (mit Java-Vergleich)

  • class EchoServer(val sn: SimpleNetwork, val address: String)
    – Kotlin-Klasse mit zwei Konstruktorparametern.
    – val bedeutet: es werden automatisch Felder angelegt (wie private final in Java).
  • init { ... }
    – Der init-Block wird direkt nach dem Konstruktor ausgeführt.
    – Hier registriert sich der Server über sn.provide(...) im Netzwerk.
  • sn.provide(address, object : ConnectionHandler { ... })
    – Entspricht sn.provide(address, new ConnectionHandler() { ... }) in Java.
    – object : ConnectionHandler { ... } ist eine anonyme Klasse mit Override der Callback-Methoden.
  • override fun onMsg(endPoint: EndPoint, msg: String)
    – Wird vom Netzwerk aufgerufen, wenn der Client sendMsg() benutzt.
    – Der Server loggt und schickt ein Echo mit <...> zurück: endPoint.sendMsg("<$msg>").
  • override fun onData(...)
    – Hier könnte man für Objekte (sendData) ein analoges Echo bauen: endPoint.sendData(data).
    – TODO("Not yet implemented") löst eine Exception aus, falls jemand trotzdem sendData auf dem Client nutzt – als Erinnerung, dass hier noch Arbeit fehlt.
  • val connected = sn.provide(...)
    – provide liefert true, wenn unter address noch kein anderer Server registriert ist.
    – Bei false wäre die Adresse schon belegt.

4.3 Ablauf-Beispiel

  1. Client verbindet sich mit derselben address über connect().
  2. Das Framework richtet eine SimpleNetworkConnection ein und ruft onOpen beim EchoServer auf.
  3. Der Client schickt sendMsg("Hallo").
  4. onMsg(..., "Hallo") wird am Server aufgerufen.
  5. Der Server antwortet mit <Hallo>.
