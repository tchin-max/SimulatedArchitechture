Blatt 4 – Aufgabe 4: Broker-Architektur (Order, Payment, Shipping, IMAP)

Autor: Tchinda Souleyman Sahlong
Modul: Softwarearchitekturen / Verteilte Systeme

1. Ziel der Aufgabe

In Aufgabe 4 soll eine kleine Microservice-ähnliche Architektur mit einem Broker umgesetzt werden. Einzelne Komponenten (Order, Payment, Shipping, IMAP) sprechen nicht direkt miteinander, sondern nur mit dem Broker.

Die Rollen:

  • BrokerServer – zentrale Vermittlungsstelle.
  • OrderComponent – nimmt Bestellungen an und koordiniert Payment, Versand und Mail.
  • PaymentComponent – simuliert die Zahlungsabwicklung.
  • ShippingComponent – simuliert den Versand von Waren.
  • ImapComponent – simuliert das Versenden einer E-Mail (Konsolenausgabe).

2. Nachrichten-Typen (DTOs)

data class MsgRegister(val name: String)
data class PaymentRequest(val corrId: String, val account: String, val amount: Double)
data class PaymentResponse(val corrId: String, val success: Boolean)
data class ShipRequest(val corrId: String, val items: List<String>)
data class ShipResponse(val corrId: String, val success: Boolean)
data class Mail(val to: String, val subject: String, val body: String)
data class GenericForward(val to: String, val payload: Any)
  • MsgRegister – Komponente meldet sich beim Broker unter einem Namen (z.B. "order") an.
  • PaymentRequest/PaymentResponse – Anfrage für eine Zahlung und die Antwort dazu.
  • ShipRequest/ShipResponse – Anfrage für den Versand und die Antwort.
  • Mail – Nachricht an den IMAP-Dienst.
  • GenericForward – allgemeiner Umschlag: „Bitte Payload an Komponente X weiterleiten“.

3. BrokerServer – zentrale Vermittlung

3.1 Code

class BrokerServer(sn: SimpleNetwork, val address: String) {

    private val components = mutableMapOf<String, EndPoint>()

    init {
        println("=== BrokerServer starting at $address ===")
        sn.provide(address, object : ConnectionHandler {

            override fun onOpen(endPoint: EndPoint) {
                println("Broker: component connected")
            }

            override fun onClose(endPoint: EndPoint) {
                val removed = components.filterValues { it == endPoint }.keys
                removed.forEach {
                    components.remove(it)
                    println("Broker: unregistered $it")
                }
            }

            override fun onMsg(endPoint: EndPoint, msg: String) {
                // Text-Nachrichten würden hier verarbeitet, wird aber nicht benötigt
            }

            override fun onData(endPoint: EndPoint, data: Any) {
                when (data) {

                    is MsgRegister -> {
                        components[data.name] = endPoint
                        println("Broker: registered component '${'$'}{data.name}'")
                        endPoint.sendData("REGISTERED:${'$'}{data.name}")
                    }

                    is GenericForward -> {
                        val target = data.to
                        val payload = data.payload
                        val dest = components[target]
                        if (dest != null) {
                            dest.sendData(payload)
                        } else {
                            println("Broker: Unknown target '$target' for GenericForward")
                            endPoint.sendData("ERROR:Unknown target $target")
                        }
                    }

                    is PaymentRequest -> {
                        val paymentEP = components["payment"]
                        if (paymentEP != null) {
                            println("Broker: forward PaymentRequest ${'$'}{data.corrId} to payment")
                            paymentEP.sendData(data)
                        } else {
                            println("Broker: no payment component registered")
                            endPoint.sendData(PaymentResponse(data.corrId, false))
                        }
                    }

                    is ShipRequest -> {
                        val shipEP = components["shipping"]
                        if (shipEP != null) {
                            println("Broker: forward ShipRequest ${'$'}{data.corrId} to shipping")
                            shipEP.sendData(data)
                        } else {
                            println("Broker: no shipping component")
                            endPoint.sendData(ShipResponse(data.corrId, false))
                        }
                    }

                    is Mail -> {
                        val imap = components["imap"]
                        if (imap != null) {
                            imap.sendData(data)
                        } else {
                            println("Broker: no imap registered")
                        }
                    }

                    else -> {
                        println("Broker: onData unknown type: ${'$'}{data::class.java.simpleName}")
                    }
                }
            }
        })
    }
}

3.2 Erklärung

  • components: MutableMap<String, EndPoint> – speichert alle registrierten Komponenten:
    • Key: Name der Komponente (z.B. "order", "payment").
    • Value: EndPoint dieser Komponente.
  • MsgRegister:
    • Komponente sendet z.B. MsgRegister("order") an den Broker.
    • Broker speichert components["order"] = endPoint.
  • GenericForward:
    • data.to ist der Zielname (z.B. "order").
    • Broker sucht den EndPoint in components[data.to].
    • Wenn vorhanden → payload wird an diesen EndPoint geschickt.
  • PaymentRequest, ShipRequest, Mail:
    • werden hier direkt an bestimmte Namen geroutet: "payment", "shipping", "imap".
    • Falls die entsprechende Komponente nicht registriert ist, gibt der Broker eine Fehlerreaktion aus (z.B. PaymentResponse(..., success = false)).

4. OrderComponent – Bestellungen orchestrieren

4.1 Code

class OrderComponent(sn: SimpleNetwork, brokerAddress: String) {
    private lateinit var ep: EndPoint

    init {
        sn.connect(brokerAddress, object : ConnectionHandler {

            override fun onOpen(endPoint: EndPoint) {
                ep = endPoint
                ep.sendData(MsgRegister("order"))
            }

            override fun onMsg(endPoint: EndPoint, msg: String) {
                println("Order got msg: $msg")
            }

            override fun onData(endPoint: EndPoint, data: Any) {
                when (data) {
                    is PaymentResponse -> {
                        if (data.success) {
                            println("Order: Payment OK for ${'$'}{data.corrId}")
                            ep.sendData(
                                ShipRequest(
                                    data.corrId,
                                    listOf("items-for-${'$'}{data.corrId}")
                                )
                            )
                        } else {
                            println("Order: Payment FAILED for ${'$'}{data.corrId}")
                            ep.sendData(
                                Mail(
                                    "customer@example.com",
                                    "Payment failed",
                                    "Payment failed for order ${'$'}{data.corrId}"
                                )
                            )
                        }
                    }

                    is ShipResponse -> {
                        if (data.success) {
                            println("Order: Shipping OK for ${'$'}{data.corrId}")
                            ep.sendData(
                                Mail(
                                    "customer@example.com",
                                    "Order shipped",
                                    "Your order ${'$'}{data.corrId} has been shipped."
                                )
                            )
                        } else {
                            println("Order: Shipping FAILED for ${'$'}{data.corrId}")
                            ep.sendData(
                                Mail(
                                    "customer@example.com",
                                    "Shipping failed",
                                    "Shipping failed for order ${'$'}{data.corrId}."
                                )
                            )
                        }
                    }

                    else -> println("Order: unknown data type ${'$'}{data::class.simpleName}")
                }
            }

            override fun onClose(endPoint: EndPoint) { }
        })
    }

    fun startOrder(items: List<String>, account: String) {
        val corr = "C" + System.currentTimeMillis().toString().takeLast(5)
        println("Order: starting order $corr for account $account with items $items")
        val amount = items.size * 10.0
        ep.sendData(PaymentRequest(corr, account, amount))
    }
}

4.2 Ablauf

  1. Verbindung & Registrierung:
    • OrderComponent verbindet sich mit dem Broker.
    • In onOpen wird ep gesetzt und MsgRegister("order") gesendet.
  2. Neue Bestellung:
    • startOrder(items, account) erzeugt eine Korrelation-ID corr.
    • Betrag wird vereinfacht berechnet: items.size * 10.0.
    • Es wird ein PaymentRequest an den Broker geschickt.
  3. PaymentResponse:
    • Bei Erfolg → ShipRequest wird gesendet.
    • Bei Fehler → eine Mail mit „Payment failed“ wird gesendet.
  4. ShipResponse:
    • Bei Erfolg → Mail mit „Order shipped“.
    • Bei Fehler → Mail mit „Shipping failed“.

5. Weitere Komponenten (Payment, Shipping, IMAP)

Die anderen Komponenten folgen alle demselben Muster:

  • PaymentComponent:
    • Verbindet sich mit dem Broker.
    • Registriert sich mit MsgRegister("payment").
    • Reagiert auf PaymentRequest und schickt PaymentResponse zurück (meist über GenericForward("order", ...)).
  • ShippingComponent:
    • Ähnlich zu Payment, aber für ShipRequest/ShipResponse.
  • ImapComponent:
    • Registriert sich als "imap".
    • Reagiert auf Mail-Objekte und gibt die Mail auf der Konsole aus.

6. Demo-Programm: BrokerDemo.kt

fun main() {
    val sn = SimpleNetwork()
    val brokerAddress = "broker://local"

    val broker = BrokerServer(sn, brokerAddress)

    // Komponenten starten (sie registrieren sich beim Broker)
    val imap = ImapComponent(sn, brokerAddress)
    val payment = PaymentComponent(sn, brokerAddress)
    val shipping = ShippingComponent(sn, brokerAddress)
    val order = OrderComponent(sn, brokerAddress)

    Thread.sleep(200) // kurz warten, bis alle registriert sind
    println("=== Simulate an order now ===")
    order.startOrder(listOf("itemA", "itemB", "itemC"), "ACC-987654")
    Thread.sleep(800)
    println("=== Demo finished ===")
}

7. Fazit

Aufgabe 4 zeigt, wie man mit einfachen Mitteln ein Broker-Pattern umsetzen kann: Alle Komponenten sind lose gekoppelt und kennen nur die Adresse des Brokers. Das eigentliche Routing übernimmt die zentrale BrokerServer-Klasse.
