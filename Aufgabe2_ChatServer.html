Blatt 4 – Aufgabe 2: ChatServer (IDs & Routing)

Autor: Tchinda Souleyman Sahlong
Modul: Softwarearchitekturen / Verteilte Systeme

1. Ziel der Aufgabe

Der ChatServer erweitert die Echo-Idee aus Aufgabe 1:

  • Jeder Client bekommt eine eindeutige ID.
  • Clients können Nachrichten gezielt an eine bestimmte ID schicken.
  • Der Server speichert und verwaltet die Zuordnung ID ↔ EndPoint.

2. Datenklassen für ID-Vergabe und Nachrichten

data class AssignId(val id: Int)
data class SendMessage(val msg: String, val toId: Int, val fromId: Int)
  • AssignId wird vom Server an einen Client geschickt, wenn dieser sich verbindet.
  • SendMessage ist die eigentliche Chat-Nachricht:
    • msg – der Text
    • toId – Ziel-Client
    • fromId – Absender-Client

3. Implementierung des ChatServers

3.1 Code

class ChatServer(sn: SimpleNetwork, address: String) {
    init {
        println("========= Start up chat server at $address ========= ")
        // Map: Client-ID -> EndPoint
        val clients: MutableMap<Int, EndPoint> = HashMap()
        // Map: EndPoint -> Client-ID (Richtung zurück)
        val endPointsToIds: MutableMap<EndPoint, Int> = HashMap()
        var freeId = 1 // nächste freie ID

        val connected = sn.provide(address, object : ConnectionHandler {

            override fun onMsg(endPoint: EndPoint, msg: String) {
                println("SERVER ($address), got msg: '$msg'")
            }

            override fun onData(endPoint: EndPoint, data: Any) {
                println("SERVER ($address), got data: '$data'")
                when (data) {
                    is SendMessage -> {
                        val toId = data.toId
                        val client = clients[toId]
                        val fromId = endPointsToIds[endPoint]
                        // Sicherheitscheck: stimmt die fromId wirklich?
                        if (fromId == data.fromId) {
                            client?.sendData(data)
                        }
                    }
                }
            }

            override fun onClose(endPoint: EndPoint) {
                println("SERVER ($address): client disconnected.")
            }

            override fun onOpen(endPoint: EndPoint) {
                println("SERVER ($address): client connected.")
                clients[freeId] = endPoint
                endPointsToIds[endPoint] = freeId
                endPoint.sendData(AssignId(freeId))
                freeId += 1
            }

        })
        if (connected) {
            println("SERVER ($address) started, listing to address $address")
        }
    }
}

3.2 Zentrale Datenstrukturen

  • clients: MutableMap<Int, EndPoint>
    – ordnet einer Client-ID den zugehörigen EndPoint zu.
    – damit kann der Server später gezielt an einen Client senden.
  • endPointsToIds: MutableMap<EndPoint, Int>
    – Rückrichtung: welcher EndPoint gehört zu welcher ID?
    – der Server kann so feststellen, welcher Client gerade sendet.
  • var freeId = 1 – Zähler für die nächste freie ID.

3.3 Ablauf beim Verbindungsaufbau

onOpen(endPoint: EndPoint) wird vom Netzwerk aufgerufen:

  1. Server loggt: „client connected“.
  2. Der EndPoint wird in clients[freeId] eingetragen.
  3. Der EndPoint wird auch in endPointsToIds[endPoint] gespeichert.
  4. Der Server sendet AssignId(freeId) an den Client.
  5. freeId wird um 1 erhöht.

3.4 Ablauf beim Empfang einer Nachricht

Wird onData mit einem SendMessage-Objekt aufgerufen, passiert:

  1. Der Server liest toId aus dem Objekt:
  2. Er ruft clients[toId] auf → Ziel-EndPoint (kann null sein).
  3. Er schaut in endPointsToIds[endPoint] nach, welcher Client gerade sendet → fromId.
  4. Er vergleicht fromId mit data.fromId:
    • Wenn sie übereinstimmen → Nachricht wird weitergeleitet.
    • Wenn nicht → der Server ignoriert die Nachricht (Schutz vor ID-Spoofing).
  5. Weiterleitung erfolgt mit client?.sendData(data):
    • Der Safe-Call-Operator ?. verhindert NullPointerException.
    • Wenn client == null, passiert einfach nichts.
